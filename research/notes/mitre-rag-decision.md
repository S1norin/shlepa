## Decision (user)

| Dimension | Decision |
|---|---|
| Retrieval approach | **Option 3 — hierarchical, cheat-based**: names-only index of the full matrix as a stable prompt prefix + read-only stdlib `mitre_kb` tool (exact-ID/substring first, then pure-Python BM25, token-capped) serving distilled cheat rows |
| KB scope | **Full matrix** — all 709 live Enterprise patterns (233 top-level + 476 sub-techniques), not the 21-block required subset |
| Compression level | **(b) cheat sheet as the retrieval payload** + (c) names-only index in prefix; **(a) field-pruned verbatim rows shipped in the zip as an opt-in higher-fidelity fallback mode** (user-confirmed) |
| ATT&CK version | **Enterprise v19.2, pinned**: `mitre-attack/attack-stix-data` @ `6cda5ad8`, `enterprise-attack-19.2.json` (53,835,637 B) |
| Target KB size | Prefix **10,577 tok** (index 8,571 + alias 2,006); zip payload **≈1.40 MB** (cheats 207,562 B + (a) rows 1,190,117 B + index/alias ≈31 KB); submission zip must stay ≤10 MB |

This **consciously refines** the survey's A2+B2 recommendation (#89): the
prefix and tool design are unchanged, but the on-demand corpus is level (b)
cheats instead of (a) field-pruned rows — 5-6× cheaper per call (~380 tok vs
~2,130 tok per top-5) at the documented paraphrase fidelity cost. The (a)
rows remain available in the zip for the fallback mode, preserving B2's
design where a cheat is ambiguous. Level-(b) quality caveats from the
compression note (cheats generalize; id/name asserted equal to source;
artifact pinned) carry over as build requirements.

## Mandatory in every scope (fixed)

- **Old→new alias map** (105 entries, 2,006 tok) in the KB data: graders
  string-match old IDs (e.g. `T1562.001` for amsi-bypass, which is `T1685`
  in v19.2). The KB answers both forms; the prompt snippet reminds the
  agent to echo the grader's accepted ID.
- Retrieval code is **stdlib-only** (no new agent deps), offline, no
  network.

## Sub-decisions

1. **Ship (a) verbatim fallback rows in the zip: yes** (user-confirmed,
   2026-09-03). Opt-in fallback mode; total zip ≈1.4 MB, far under 10 MB.
2. **Query interface**: single query string; if it contains a T-ID,
   exact/substring match wins, else BM25 fallback. (Recommended default;
   not explicitly confirmed by the user — open until build starts.)
3. **Prefix index format**: bare `T-ID Name` lines, no tactic grouping.
   (Recommended default; open until build. Revisit after A/B if the agent
   struggles to scan it.)
4. **Cheat regeneration policy**: pin the generated artifact now;
   regenerate only on an ATT&CK version bump, as a scripted, diff-checked
   event. (Recommended default; open until build.)

## Build spec (binding for `kb-artifact` and `mitre-kb-tool`)

- Artifact(s) under `agent/shlepa_agent/kb/`, generated by
  `scripts/build_mitre_kb.py` from the pinned bundle + pinned
  `cheat-all.jsonl` (the generator never calls an LLM — deterministic;
  cheats are a pinned generated artifact copied from scratch, asserted
  byte-stable across regeneration).
- Build script asserts: every cheat row's `id`/`name` equals its source
  (a) row; artifact header records ATT&CK version (`19.2`) + generation
  date + source commit.
- `mitre_kb` tool: read-only; returns top-5 rows by default, token-capped;
  cheat mode is the default, a tool parameter selects the (a)-rows
  fallback mode.
- Prompt wiring: index + alias map + alias-echo reminder as an
  arm-gated stable prefix on the `+mitre-kb` arm.
- Prefix cost check during build: verify KV-cache behavior via the
  existing `tokens_cache_read` telemetry in the A/B (survey open item).
